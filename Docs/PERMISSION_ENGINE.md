# Permission Engine

The Permission Engine composes permissions from ownership, roles, capabilities, policies, delegation, and context.

## Actions
Read, write, update, delete, execute, share, publish, export, clone, fork, merge, benchmark, review, and admin.

## Composition
Permissions can be direct, inherited, delegated, role-derived, policy-derived, organization-derived, community-derived, or temporary.

## Capability Examples
Question capabilities include `canBeAnswered`, `canBeBenchmarked`, `canBeLinked`, and `canBecomeProject`.

Project capabilities include `canPublish`, `canFork`, `canArchive`, and `canCollaborate`.

## UI Behavior
Capabilities should drive UI affordances. Hidden or disabled actions must match authorization decisions.
