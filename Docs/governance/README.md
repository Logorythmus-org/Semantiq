## Current governance

SemantIQ's current repository governance is defined by:

- 🏛️ **[Repository Governance](../../GOVERNANCE.md)** (`NORMATIVE`): current maintainer authority, contribution paths, RFC relationship, and maturity boundary.
- 👥 **[Code Ownership Mappings](../../.github/CODEOWNERS)** (`NORMATIVE`): authoritative path-to-team review rule.
- 📋 **[Request for Comments Process](rfc_process.md)** (`NORMATIVE PROCESS`): review path for material architectural, scientific, contract, governance, and security proposals.
- 🤝 **[Contributing](../../CONTRIBUTING.md)** (`NORMATIVE`): Fast and Core contribution workflows.
- 🧭 **[Support Routing](../../SUPPORT.md)** (`NORMATIVE`): questions, defects, proposals, security, and replication-report channels.

## Proposed and historical governance material

- **[Product-Domain Governance Model](../GOVERNANCE.md)** (`PROPOSED / HISTORICAL`): broader 10-domain ownership model retained as planning provenance; it is not the current GitHub authority.
- **[Prospective IP Architecture](ip-architecture.md)** (`PROPOSED`): public, research-prepublication, and protected boundaries for future development; not a rights determination.
- **[Controlled Research-Start Governance](research-start-governance.md)** (`PROPOSED`): proposed provenance, input, Cyber-sensitivity, and publication controls for restricted strategic research.

The existence of a proposed council, domain team, working group, or foundation in
a planning document does not establish that body as active repository governance.
