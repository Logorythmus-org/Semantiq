# Support

SemantIQ is currently **Public Alpha (Experimental)**. This repository does not
publish a guaranteed support SLA, paid support commitment, or 24/7 response
service.

Use the route that best matches the request.

## Usage, installation, and documentation

For a bounded documentation problem, unclear example, installation mismatch, or
usage question that can be discussed publicly, open a
[Documentation Improvement](https://github.com/Logorythmus-org/Semantiq/issues/new?template=docs_improvement.yml)
or a
[Reproduction / Compatibility Report](https://github.com/Logorythmus-org/Semantiq/issues/new?template=reproduction_report.yml).

Include the exact SemantIQ commit/version, environment, commands, and observed
behavior when relevant.

## Reproducible defects and compatibility observations

Use the
[Reproduction / Compatibility Report](https://github.com/Logorythmus-org/Semantiq/issues/new?template=reproduction_report.yml).

Do not include credentials, private datasets, proprietary prompts, or personal
data.

## Feature, connector, benchmark, and architecture proposals

Use the matching GitHub issue form:

- Feature Request
- Model Connector Request
- Benchmark Pack Proposal
- Architecture / RFC Proposal
- Research Methodology Proposal
- Partner / Protocol Integration Proposal

Submission starts a review process. It does not establish acceptance, partnership,
endorsement, roadmap commitment, or external validation.

## Independent replication

Use the
[Independent Replication Report](https://github.com/Logorythmus-org/Semantiq/issues/new?template=independent_replication_report.yml).

A submitted or successful reproduction attempt remains a submission until its
provenance and independence are reviewed.

## Security vulnerabilities

Do **not** disclose vulnerability details in a public issue.

Follow [SECURITY.md](SECURITY.md) for the repository's current vulnerability
reporting policy and evidence boundary.

## Conduct concerns

Read the [Code of Conduct](.github/CODE_OF_CONDUCT.md).

Do not post sensitive conduct details in a public issue. For conduct occurring on
GitHub, use GitHub's platform reporting and safety mechanisms where appropriate.
If a project-specific private route is needed and none is explicitly listed, open
only a non-sensitive process question asking maintainers how to continue
privately; do not include incident details.

## Governance and contribution process

- [Contributing](CONTRIBUTING.md)
- [Governance](GOVERNANCE.md)
- [CODEOWNERS](.github/CODEOWNERS)

Support responses are best-effort during Public Alpha and do not create a
production support or service-level commitment.
