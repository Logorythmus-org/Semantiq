# Support

SemantIQ is a Public Alpha project. Use the channel that best matches the kind of
help or report you need.

## Usage and setup questions

Use [GitHub Discussions](https://github.com/Logorythmus-org/Semantiq/discussions)
for questions about setup, local usage, interpretation of documentation, and
general project discussion.

## Community navigation

- [Community Hub](COMMUNITY.md) — choose the right participation path.
- [GitHub Discussions](https://github.com/Logorythmus-org/Semantiq/discussions) — questions, ideas, results, and early proposals.
- [GitHub Projects](https://github.com/Logorythmus-org/Semantiq/projects) — current coordination and contribution opportunities.
- [GitHub Wiki](https://github.com/Logorythmus-org/Semantiq/wiki) — orientation and learning material.

The Project board and Wiki are coordination/navigation surfaces, not replacements for reviewed repository truth.

## Reproducible defects and compatibility problems

Open a
[Reproduction or Compatibility Report](https://github.com/Logorythmus-org/Semantiq/issues/new?template=reproduction_report.yml).

Include the smallest reproducible example, environment details, observed
behavior, and expected behavior. Remove credentials, private data, and
proprietary inputs.

## Feature and architecture proposals

- [Feature Request](https://github.com/Logorythmus-org/Semantiq/issues/new?template=feature.yml)
- [Architecture / RFC Proposal](https://github.com/Logorythmus-org/Semantiq/issues/new?template=architecture_rfc.yml)
- [Benchmark Pack Proposal](https://github.com/Logorythmus-org/Semantiq/issues/new?template=benchmark_pack_proposal.yml)
- [Research Methodology Proposal](https://github.com/Logorythmus-org/Semantiq/issues/new?template=research_methodology.yml)
- [Documentation Improvement](https://github.com/Logorythmus-org/Semantiq/issues/new?template=docs_improvement.yml)

A proposal is a request for review. Opening an issue does not establish approval,
commitment, partnership, external validation, or a release promise.

## Independent reproduction

Use the
[Independent Replication Report](https://github.com/Logorythmus-org/Semantiq/issues/new?template=independent_replication_report.yml)
for third-party reproduction attempts.

Submission, including a successful reproduction, is not automatically
`VERIFIED_EXTERNAL_REPLICATION`; provenance and independence still require
review.

## Security vulnerabilities

Do **not** put vulnerability details in a public issue.

Review the [Security Policy](SECURITY.md) and GitHub's
[repository security-policy view](https://github.com/Logorythmus-org/Semantiq/security/policy)
before disclosing sensitive security information.

## Code of Conduct

The [Code of Conduct](.github/CODE_OF_CONDUCT.md) applies to project
participation.

The repository does not currently publish a dedicated private conduct-reporting
endpoint. Do not place sensitive personal or conduct-report details in a public
issue merely to reach maintainers. A dedicated private conduct channel must be
established separately before the project can claim private conduct intake.

## Maintainer review

Repository changes remain subject to the protected-branch, required-check, and
CODEOWNER rules described in [Governance](GOVERNANCE.md) and
[Contributing](CONTRIBUTING.md).
